# Выполненные проверки — 22 октября 2026

Проверки выполнены на Windows 11 Pro (build 26200), Intel Core i5-12400F,
32 ГБ RAM, NVIDIA RTX 4060 Ti 8 ГБ. Python 3.11.9; PyTorch 2.5.1 CPU / CUDA 12.1.
Основная модель — реальные EMA-веса `ytre0o0/MeanVC2-ru`,
SHA256 `65774b2ef58f1ed8a588813383d6e17b3e2e19c731375d0abc7b6022c93c3e51`.
Профиль 120ms+40ms, 2 шага, 1 поток CPU. Результаты относятся к этой машине;
параллельно работали обычные desktop-приложения, это не изолированный performance lab.

## Скорость

Время только потоковой обработки, без первоначальной загрузки/WavLM reference
encoding. Один входной блок = 160 мс. RTF < 1 означает, что средняя обработка
быстрее поступления аудио. Холодный старт и отдельные пики могут быть медленнее.

| Проверка | Длительность каждого прохода | Среднее время блока, два прохода | RTF |
|---|---:|---:|---:|
| Python CPU, длинный поток | 65,12 с × 2 | 36,42 / 36,65 мс | 0,228 / 0,229 |
| Python CUDA, длинный поток | 65,12 с × 2 | 40,43 / 34,23 мс | 0,253 / 0,214 |
| Финальный CPU-only EXE, Auto → CPU | 10,08 с × 2 | 38,28 / 34,73 мс | 0,239 / 0,217 |
| Финальный CUDA EXE, CUDA:0 | 10,08 с × 2 | 36,94 / 31,65 мс | 0,231 / 0,198 |

Длинные потоки проходят периодический сброс DiT KV-позиции штатного runtime.
После reset тот же объект инференса снова возвращает корректный звук. Выход
короче входа примерно на 0,22–0,30 с из-за lookahead/буферов штатного streaming:
при остановке не синтезируется искусственное продолжение речи.
Исходный и референсный WAV сгенерированы локальным Windows SpeechSynthesizer;
команда воспроизведения подготовки — `scripts/make_test_audio.ps1`.
Это проверка речевого PCM и нейросетевого тракта, не экспертная оценка похожести голоса.

Машиночитаемые результаты: `cpu-long.json`, `cuda-long.json`, `local-model.json`,
`final-cpu.json`, `final-cuda.json`. Преобразованные WAV находятся рядом с отчётами
на диске; они исключены из git. Начальные короткие замеры также сохранены.

## Реальные аудио- и GUI-сценарии

`gui-integration.json`:

* CPU: WASAPI физический микрофон → виртуальный выход; 65 блоков, входных
  переполнений 0, выходных прерываний 1, последняя оценка задержки 701 мс.
* CUDA: WASAPI виртуальный вход с речью → физический выход; 65 блоков, входных
  переполнений 0, выходных прерываний 0, последняя оценка задержки 690 мс.
  Ненулевой PCM подтверждён через `peak_level` = 0,133.
* Запись через кнопку GUI с реального виртуального Windows-входа: 3-секундный
  WAV сохранён, подготовлен и выбран. Запись через физический микрофон дала
  тишину и была корректно отклонена; реальную человеческую речь он в тесте не записывал.
* Подтверждены передача PCM через виртуальный кабель, прослушивание образца,
  импорт WAV, последовательный запуск/остановка с разными устройствами,
  сохранение и восстановление настроек.

Финальные CPU/CUDA EXE дополнительно дважды открывали системные MME-устройства
по 10 секунд: по 62 блока на запуск. Входных переполнений 0; выходных прерываний
3–4 на CPU и 4–8 на CUDA. Оценки задержки 585–591 мс и 618–630 мс соответственно.
Этот MME-путь нельзя считать проверенным на отсутствие прерываний; для данной
машины WASAPI дал более стабильный результат. Увеличение буфера доступно в GUI.
Выход в автоматических аудиопроверках был заглушён, чтобы не создавать обратную связь.

Оценки задержки учитывают возраст входного блока, очередь и PortAudio. Физический
loopback **не измерялся**; это не доказательство end-to-end задержки или 110 мс из статьи.

## Финальные дистрибутивы

* `dist/cpu/MeanVC2Desktop/`: около 497 МиБ, PyTorch `2.5.1+cpu`, CUDA runtime отсутствует,
  GPU-список пустой; Auto выбрал CPU.
* `dist/cuda/MeanVC2Desktop/`: около 3,65 ГиБ, PyTorch `2.5.1+cu121`, CPU и CUDA.
* Python DLL, Qt, PortAudio, libsndfile, soxr и VC++ runtime входят в папки.
  Модели скачиваются отдельно в `%LOCALAPPDATA%\MeanVC2Desktop`.
* Запуск EXE проверен из `%TEMP%`, с PATH, содержащим только системные Windows-папки,
  пустыми PYTHONHOME/PYTHONPATH и `HF_HUB_OFFLINE=1`. Диагностика подтверждает
  `frozen=true` и Python paths только внутри `_internal`.
* GUI smoke, реальный инференс и два цикла аудио завершились кодом 0 в обоих вариантах.
* Оригинальный checkout не требуется: после проверок он перенесён за пределы
  проекта. В репозитории остаются только используемые исходники инференса.

## Что ещё не подтверждено

* Запуск на **другом чистом компьютере без Python** и Windows 10: такой машины
  в сессии нет. Изоляция PATH на текущей Windows 11 — полезная проверка упаковки,
  но не замена этому приёмочному сценарию.
* Работа на машине физически без NVIDIA GPU, на нескольких GPU и с иными
  аудиодрайверами. CPU-only wheel реально проверен; несколько GPU покрыты unit-тестом выбора.
* Многочасовая непрерывная работа, извлечение кабеля во время записи, экспертное
  прослушивание качества и физическое измерение задержки.
* Профиль 40ms доступен и использует штатные компоненты, но реальные веса
  `MeanVC2-ru` объявляют 120ms: проверять их как 40ms приложение не позволяет.
  Отдельная официальная 40ms-модель в этих измерениях не использовалась.

Поэтому переносимость на чистый ПК и субъективное качество остаются этапами
приёмки; сборка EXE сама по себе не обозначена как подтверждение всех критериев ТЗ.
