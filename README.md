# MeanVC2 Desktop

Нативное Windows-приложение на PySide6 для потокового преобразования голоса.
Использует [официальный MeanVC2](https://github.com/ASLP-lab/MeanVC2) и
[MeanVC2-ru](https://huggingface.co/ytre0o0/MeanVC2-ru). Обучение и сервер не нужны.

## Запуск готовой сборки

Откройте `MeanVC2Desktop.exe` в папке выбранного дистрибутива.
Переносите **всю папку** `MeanVC2Desktop`, включая `_internal`.
В GitHub Releases скачайте и запустите отдельный `MeanVC2Desktop.exe`:
он сам извлекает библиотеки во временную папку. Такой запуск занимает больше
времени и требует около 3,5 ГБ свободного места для распаковки библиотек.
Python и CUDA Toolkit на целевой машине не требуются. CUDA-сборка работает
и на CPU; для GPU нужен совместимый драйвер NVIDIA. Поддерживаются Windows
10/11 x64. Сборка не подписана цифровым сертификатом.

1. Нажмите **Скачать / обновить** в разделе «Модель». Первый запуск скачивает
   примерно 1,65 ГБ: VC, ASR, Vocos, WavLM/ECAPA. Прогресс показывается в байтах.
   **Обновить список** получает доступные `.safetensors` из HF-репозитория.
2. Оставьте конфигурацию **120 мс + 40 мс** для `meanvc2_ru.safetensors`.
3. Выберите CPU, CUDA или автоматический режим; при нескольких GPU выберите карту.
4. Добавьте чистую WAV-запись целевого голоса (1–30 секунд) или запишите её
   через выбранный микрофон. WAV автоматически преобразуется в mono 16 кГц.
   Образцы можно прослушивать, удалять и переключать.
5. Выберите вход и выход. Для передачи в другое приложение выберите выход
   виртуального кабеля, затем назначьте парный вход кабеля микрофоном в том приложении.
   Частоту устройств оставьте «Автоматически»: вход и выход могут поддерживать разные частоты.
6. Нажмите **Начать преобразование**. После загрузки модели появляется статус
   «Преобразование работает». Громкость можно менять во время обработки.
7. Для смены модели, голоса или устройств остановите обработку, измените выбор
   и запустите снова. Перезапуск приложения не требуется.

Используйте наушники при выводе на физические динамики, чтобы избежать обратной связи.
Поддерживаются совместимые устройства MME, DirectSound, WASAPI и WDM-KS, которые
предоставляет PortAudio. Доступность частоты/числа каналов зависит от драйвера;
при неподдерживаемой явно выбранной частоте показывается сообщение с предложением
выбрать «Автоматически». Форматы проверяются до загрузки нейросети.
«Автоматическая частота» сначала проверяет частоту по умолчанию отдельно для
входа и выхода, затем при необходимости 48, 44,1, 16 и 96 кГц. Ресемплер сохраняет
состояние между блоками.

После скачивания интернет для инференса не используется. Все модели, образцы,
настройки и ротационные логи находятся в `%LOCALAPPDATA%\MeanVC2Desktop`.
Путь не зависит от рабочей директории и версии сборки. Для офлайн-переноса
скопируйте также эту папку в профиль пользователя на другом компьютере.

**Локальная модель…** принимает `.safetensors`, совместимый с оригинальным DiT.
Для неё также скачиваются вспомогательные модели кнопкой **Скачать / обновить**.
Проверяются ключи, размеры и конечность весов, а при наличии метаданных — профиль.
Если метаданные профиля отсутствуют, выберите правильный профиль вручную:
40ms и 120ms имеют одинаковые размеры весов, по форме их различить нельзя.

## Параметры и задержка

Доступны оба штатных профиля, число шагов ODE (1–8, по умолчанию 2), число
потоков PyTorch CPU (1–32), частота устройств, выходной буфер и громкость.
Профиль меняет ASR и контекст DiT, но не архитектуру модели. Низкоуровневые
параметры обученной сети фиксированы официальной конфигурацией.

В официальном Python runtime вход обрабатывается блоками **2560 отсчётов / 160 мс**
в обоих профилях. Поэтому название профиля «40 мс» не равно общей задержке приложения.
«Инференс» — время обработки последнего блока. «Задержка тракта ≈» — оценка
возраста входного блока плюс выходная очередь и задержки PortAudio; это не
измерение через физический loopback. На показатель влияют ASR/DiT-контекст,
буферизация, частоты и драйверы. Если CPU не успевает, уменьшите число шагов,
проверьте число потоков или выберите CUDA. Очереди ограничены: при устойчивой
перегрузке приложение останавливается с объяснением вместо нарастания задержки.

## Запуск из исходников

Требуется Python **3.11 x64**. В PowerShell из корня проекта:

```powershell
git submodule update --init --recursive
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
# Универсальная сборка CUDA 12.1 + CPU:
.\.venv\Scripts\python.exe -m pip install torch==2.5.1 torchaudio==2.5.1 --index-url https://download.pytorch.org/whl/cu121
.\.venv\Scripts\python.exe -m pip install -e '.[build]'
.\.venv\Scripts\python.exe -m app.main
```

Для окружения без CUDA используйте индекс `https://download.pytorch.org/whl/cpu`.
Официальный репозиторий MeanVC2 подключён как git submodule в `third_party/MeanVC2`
на commit `13acf84c1bf135ea5edad9c245b345289b06b33e`, без изменений его файлов.
При клонировании проекта используйте `git clone --recurse-submodules <URL проекта>`
или команду инициализации выше. Архивы GitHub «Source code» не содержат submodule:
для разработки нужен Git checkout. Готовый EXE от Git не зависит.
Адаптер импортирует `runtime/run_rt.py` и `runtime/src` напрямую; код обучения
не импортируется и не включается в EXE. В `app/vendor/s3prl` остаётся минимальная
оригинальная часть WavLM, чтобы не устанавливать тренировочные s3prl/fairseq.
Загрузка файлов, проверка весов и выбор GPU находятся в `app/inference.py`.
При стандартных двух шагах ODE вызывается штатный метод MeanVC2; для другого
числа шагов используется отдельное расширение адаптера.
Происхождение компонентов описано в [THIRD_PARTY.md](THIRD_PARTY.md).

## Сборка EXE

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build.ps1 -Variant cuda
# Меньшая сборка только с CPU, в отдельном окружении:
powershell -ExecutionPolicy Bypass -File scripts/build.ps1 -Variant cpu
# Один EXE с CPU и CUDA, как в GitHub Releases:
powershell -ExecutionPolicy Bypass -File scripts/build.ps1 -Variant cuda -OneFile
```

Скрипт получает зафиксированный submodule, проверяет коды завершения установки, запускает тесты, собирает `onedir`
и проверяет диагностику EXE. Результат — `dist/<вариант>/MeanVC2Desktop/`.
С `-OneFile` результат — `dist/<вариант>-onefile/MeanVC2Desktop.exe`.
`-SkipInstall` использует уже подготовленное окружение. `requirements-lock.txt`
фиксирует общие зависимости проверенных окружений и используется сборщиком;
вариант PyTorch задаётся отдельным индексом, основные версии закреплены
в `pyproject.toml`. Для архивирования готовой папки можно использовать 7-Zip.

## Релиз кнопкой в GitHub

После загрузки проекта на GitHub файл `.github/workflows/release.yml` должен
находиться в основной ветке репозитория, чтобы появилась кнопка ручного запуска.

1. Откройте **Actions → Build and publish Windows release → Run workflow**.
2. Выберите ветку и укажите новый тег, например `v1.0.1` (формат `vX.Y.Z`).
3. Нажмите **Run workflow**. После успешной сборки откройте **Releases**.

Workflow получает submodule на зафиксированном commit и собирает один CUDA-enabled EXE с поддержкой CPU на Windows x64,
запускает тесты, проверяет диагностику и GUI на runner без GPU. В релиз
загружается один файл `MeanVC2Desktop.exe`. Модели в него не входят
и скачиваются через приложение.
Стандартные ссылки GitHub **Source code (zip/tar.gz)** добавляются самой платформой.

Дополнительный PAT не требуется: используется `GITHUB_TOKEN` с `contents: write`.
Существующие теги не перезаписываются. При ошибке загрузки публикация не происходит,
может остаться черновик релиза; удалите его перед повторной попыткой с тем же тегом.
Перед загрузкой проверяются наличие EXE, ненулевой размер и лимит менее 2 ГиБ.
Фактический CUDA-инференс и аудиооборудование workflow не проверяет.
Для соблюдения лимита onefile-сборка исключает только
`cudnn_engines_precompiled64_9.dll`: официальный инференс отключает cuDNN.
При включении cuDNN эту библиотеку необходимо вернуть; обычная onedir-сборка её сохраняет.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m app.main --diagnostics reports/environment.json
.\.venv\Scripts\python.exe -m app.main --smoke-test reports/gui.png
powershell -ExecutionPolicy Bypass -File scripts/make_test_audio.ps1
.\.venv\Scripts\python.exe -m app.main --benchmark reference.wav --source source.wav --device cpu --seconds 30 --report reports/cpu.json
.\.venv\Scripts\python.exe -m app.main --benchmark reference.wav --source source.wav --device cuda --seconds 30 --report reports/cuda.json
```

Бенчмарк использует реальные скачанные веса, два прохода со сбросом кешей,
проверяет конечный ненулевой результат и сохраняет преобразованные WAV.
`--audio-test` дополнительно дважды открывает реальные устройства и запускает
аудиопоток; выход заглушён. Устройства задаются `--input-device N --output-device N`
(индексы есть в диагностике). Эти аргументы поддерживаются и собранным EXE.
`scripts/verify_gui.py` проверяет реальные сценарии GUI, используя тестовый WAV.
Для него нужны доступные WASAPI-вход/выход и установленный VB-Audio Cable;
это требование проверочного сценария, приложение работает и без виртуального кабеля.

Фактические результаты и ограничения: [reports/VALIDATION.md](reports/VALIDATION.md).
Проверки после перехода на submodule и пересборки единого EXE:
[reports/SUBMODULE.md](reports/SUBMODULE.md).
Наличие EXE и успешные тесты не заменяют прослушивание качества, измерение
физической задержки и проверку на отдельном компьютере без Python.

## Структура

`app/gui.py` — Qt и управление состоянием; `models.py` — HF и кеш;
`inference.py` — адаптер официального runtime; `audio.py` — захват, очереди,
ресемплинг, воспроизведение и образцы; `settings.py` — настройки/логи;
`checks.py` — диагностика и воспроизводимые измерения. Инференс и длительные
операции работают в worker-потоке; аудиоколбэки только перемещают буферы.
`upstream.py` — пути импорта официального runtime из `third_party/MeanVC2`;
`app/assets` — небольшая конфигурация WavLM. Копий исходников MeanVC2 в `app` нет.
